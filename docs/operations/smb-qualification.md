# SQLite-on-SMB qualification gate

MolKey's shared SQLite registry is **not production-approved** until this gate passes on the actual hospital UNC share from at least two authorized workstations.

## Safety

- Use only the synthetic `CASE-SMB-*`, `PAT-SMB-*`, and `SMB*` records generated by the script.
- Do not use patient data during qualification.
- Coordinate the test with hospital IT because it exercises concurrent file locking and network interruption.
- Back up any existing registry before testing.

## 1. Baseline concurrent writers

From workstation A:

```bash
uv run python scripts/qualify_smb.py "//server/secure-share/MolKey" --workers 4 --writes 25
```

Repeat from workstation B while workstation A is still running, increasing `--writes` if necessary to overlap the runs.

Pass criteria:

- `passed` is `true`
- `integrity_check` is `ok`
- `journal_mode` is `DELETE`
- all worker exit codes are `0`
- `errors` is empty
- observed synthetic rows are at least the expected count

## 2. Forced process termination

1. Start a longer run (`--workers 8 --writes 1000`).
2. Terminate one worker process from Task Manager while writes are active.
3. Let the remaining workers finish.
4. Run `PRAGMA integrity_check` by running the qualification script again with a small workload.

Pass criteria:

- The terminated operation is reported as failed, not silently successful.
- The database opens from both workstations.
- `PRAGMA integrity_check` returns `ok`.
- No partially committed case row is visible.

## 3. Network interruption

With hospital IT approval:

1. Start a long qualification run.
2. Briefly interrupt the workstation's access to the share while a writer is active.
3. Restore access.
4. Verify the app reports a bounded busy/I/O error and remains usable after reconnect.
5. Re-run the baseline qualification and integrity check.

Pass criteria:

- No indefinite hang.
- No false success message.
- Database integrity remains `ok`.
- Subsequent writes and reads succeed.

## 4. Backup and restore

1. Create an online SQLite backup while the registry is idle.
2. Restore it to a separate approved test folder.
3. Run the qualification script against the restored registry.
4. Compare row counts and schema version with the source.

Pass criteria:

- Restored database integrity is `ok`.
- Schema version and row counts match.
- Wrapped-key records remain byte-identical.

## Evidence to retain

Record the date, UNC path, workstation names, Windows versions, SMB/server details, script output, interruption observations, integrity results, backup/restore results, tester names, and IT/security approval. Do not include patient identifiers or key material.

> A passing local simulation validates the test harness only. It does not satisfy this release gate.
